# Checklist — Pre-flight (avant de générer les variantes)

> À cocher **avant** d'écrire la moindre variante. Si une case n'est pas cochée → demander au user, ne pas inventer.

---

## Inputs minimum vitaux

- [ ] Nom du client + slug
- [ ] Secteur identifié (SaaS B2B / Agency / Coaching / Consulting)
- [ ] Offre actuelle décrite (outcome, timeframe, méthode, garantie, pricing)
- [ ] Audit Value Equation réalisé → score /20
- [ ] Verdict : Solid / Mediocre / Weak

## Si offre Weak

- [ ] STOP génération pubs
- [ ] Document `output-offer-rebuild.md` produit
- [ ] Validation client avant de continuer

## Si offre Mediocre

- [ ] 2–3 fixes chirurgicaux proposés au client
- [ ] Validation client sur les fixes
- [ ] Audit re-scoré ≥ 16/20

## ICP & Avatar

- [ ] ICP défini (titre, secteur, taille, géo)
- [ ] Niveau de conscience Schwartz identifié (1–5)
- [ ] Niveau sophistication marché identifié (1–5)
- [ ] Pain principal en verbatim ou paraphrase courte
- [ ] Goal principal en verbatim
- [ ] Common enemy identifié

## Preuves

- [ ] Au moins 1 témoignage chiffré disponible (nom + résultat + délai)
- [ ] Garantie nommée disponible
- [ ] Mécanisme nommé disponible (sinon → en créer un avec le client)

## Demande de production

- [ ] Durées demandées clarifiées (**minimum 30s — jamais en dessous**. Default : 30s + 60s + 90s)
- [ ] Nombre de variantes par durée clarifié
- [ ] CTA cible défini (booked call / lead magnet / signup / application)
- [ ] URL LP disponible
- [ ] Voix tu/vous décidée

## Compliance & Risques

- [ ] Vérification rapide des claims interdits par Meta (santé, finance, before/after…)
- [ ] Vocabulaire sensible identifié et listé

## Pipeline aval

- [ ] Speed-to-lead < 5 min : OK ou à mentionner en note
- [ ] Congruence LP : OK ou à mentionner en note

---

> ✅ Toutes les cases obligatoires cochées → passer à Phase 4 (génération).
> ❌ Une case manque → demander au user avant de continuer.
